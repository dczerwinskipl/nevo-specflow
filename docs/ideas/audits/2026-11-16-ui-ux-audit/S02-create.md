# S02-create: Creating a Specification

Evidence only, from the [UI/UX audit of 2026-11-16](../2026-11-16-ui-ux-audit.md). Images are on the
review-only branch `ux-audit/2026-11-16`, pinned to commit `9ddf6421`. Click a thumbnail for the
full image.

## Goal

Check the Create form in its empty, invalid and filled states, the workspace/branch explanation, and what happens right after Create.

## Preconditions and data state

- **real-empty** (Real app on :4320, fresh scratch project (not demo); managed Sessions disabled): Steps 01–02 without archetype definitions; 03–08 with definitions installed. The example config has no `git` section, so “New workspace” is disabled and “Current folder” is preselected. Step 09 creates “SSO sign-in” (Feature) and step 10 creates “Spike: passkeys” (Minimal) — desktop only, one frame per visible change.
- **real-demo** (Real app, `start --demo` on :4319 (populated sample data, Sessions read-only/broken by design)): Demo catalogue.

## Steps: real-empty

Environment: Real app on :4320, fresh scratch project (not demo); managed Sessions disabled. Each step opens the URL in a fresh browser context at each device, then does the action described. Click a shot to open it; “full page” grows the viewport until the tallest scroll pane fits.

## Observations

Neutral notes only; severity is the audit’s estimate of impact on a person using the screen.

- **high** · all · With no definitions installed the footer only says “Enter a specification name. Go to the field”; the real blocker (no archetypes, a CLI command to run) sits mid-form as a small info line. <br><sub>Shots: `real-empty-*-01-form-no-definitions / 02-go-to-field-no-definitions`</sub>
- **high** · all · “New workspace — Disabled in the project configuration.” gives no hint which setting enables it; with the example config this is the default for every new project. <br><sub>Shots: `real-empty-*-03-form-with-archetypes`</sub>
- **high** · desktop · Create in the current folder leaves the new files untracked in git (`?? specs/`), but the progress page reports plain success. Storybook has a “Created but not committed” design that the real flow did not show. This later blocks Close (S07). <br><sub>Shots: `real-empty-desktop-09-after-create-02`</sub>
- **medium** · desktop · Progress step reads “Name and branch reserved” although “Current folder” creates no branch. <br><sub>Shots: `real-empty-desktop-09-after-create-02`</sub>
- **low** · desktop · “Done. Opening the specification...” ends in a trailing ellipsis; a toast “Specification created” repeats the page heading. <br><sub>Shots: `real-empty-desktop-09-after-create-02`</sub>
- **low** · desktop · The new Specification URL uses a UUID (`/specs/f497511d-…`) while demo URLs use slugs (`/specs/admission`). <br><sub>Shots: `real-empty-desktop-09-after-create-03`</sub>
- **low** · all · Archetype radios have no default; the documents list only appears after a choice (“Choose an archetype to see the documents Create makes.”). <br><sub>Shots: `real-empty-*-05-name-filled-no-archetype`</sub>
