## Goal

See the Tasks page with no Tasks, while drafting the first ones, grouped by state, and the Task detail at each state; compare with the demo and the designs.

## Preconditions and data state

- **real-empty** (Real app on :4320, fresh scratch project (not demo); managed Sessions disabled): Same “SSO sign-in” Specification. ## Observations

Neutral notes only; severity is the audit’s estimate of impact on a person using the screen.

- **high** · all · The demo Task detail (State/Flow facts, “NEXT WORK — NOT STARTED”, “Related resources 14”) and the project-mode Task detail (NOW card, Documents, Context, Depends on) are two different screens for the same object. <br><sub>Shots: `real-demo-phone-04-task-detail vs real-empty-phone-18-task-detail-in-progress`</sub>
- **medium** · all · Task detail shows internal tokens: step id in monospace (“· implement ·”), workflow name and “rev 1”. <br><sub>Shots: `real-empty-*-18-task-detail-in-progress`</sub>
- **medium** · tablet, phone · On tablet/phone the Task detail collapses Documents and Context into closed disclosures with “+” buttons, leaving most of the screen empty. <br><sub>Shots: `real-empty-phone-18-task-detail-in-progress`</sub>
- **low** · all · New task dialog validation is inline and specific (“Use lowercase letters, digits and dashes…”). <br><sub>Shots: `real-empty-*-06-new-task-bad-id`</sub>
