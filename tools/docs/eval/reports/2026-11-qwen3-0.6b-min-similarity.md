# Relevance cutoff for `qwen3-embedding:0.6b` (issue #156), November 2026

This report measures `ai.embeddings.minSimilarity` with the local `qwen3-embedding:0.6b` model on
this repository's documentation. The result is the local setting in
[local setup](../../../../docs/engineering/repository/local-setup.md#semantic-documentation-search).
That setting is a local, model-specific choice, not a product default.

`minSimilarity` is a relevance filter for vector-only candidates, not a confidence measure of
whether the documentation answers the question.

## Setup

**Corpus:** this repository's `docs/` at commit `71c94ddb`.

- 226 documents and 2,408 chunks after a full `pnpm docs:semantic index`.
- No eval query string is in the corpus. The query files live in `tools/docs/eval/`, outside
  `docs/`.

**Model:** `qwen3-embedding:0.6b`, served by Ollama on a local GPU:

```yaml
baseUrl: http://127.0.0.1:11434/v1
```

**Query instruction ("Qwen3"):** the model's own retrieval task line, with a line break before
`Query: ` and a trailing space:

```text
Instruct: Given a web search query, retrieve relevant passages that answer the query
Query:
```

The baseline ("none") runs without an instruction.

**Question sets:**

- **Tuning set:** `tools/docs/eval/questions.yaml`.
  - 60 answerable questions: 39 correct, 10 partial words and 11 typos.
  - 10 negative questions: real questions that the documentation does not answer.
  - 18 hand-written random strings.
  - The instruction and the 0.36 floor were chosen on this set.
- **Held-out set:** `tools/docs/eval/questions-holdout.yaml`.
  - 20 answerable questions: 4 correct, 8 partial words and 8 typos.
  - 5 negative questions.
  - It was written after the choice and is never used for tuning.

**Generated strings:** each run adds 150 generated random strings (`--random 150`) with seeds 7001,
7002 and 7003. The generator is mulberry32. For a given seed, both sets get the same strings.

**Metrics:** over the top 10.

- Recall@5, Recall@10 and MRR are computed over the answerable questions.
- FP (false positives) counts the questions without an answer that get at least one document found
  by meaning only (`wordMatch: false`).
- "Lost" counts the answerable questions that have an expected document in the top 10 without a
  floor and none with it.

## Commands

Run these from the repository root, with the endpoint and model in `.nevo/local/config.yaml`. Each
command prints the report as JSON. In Bash, `$'…'` passes the line break.

```bash
pnpm docs:semantic index
for seed in 7001 7002 7003; do
  for set in questions questions-holdout; do
    pnpm docs:eval --json --questions tools/docs/eval/$set.yaml --random 150 --random-seed $seed \
      --min-similarity none,0.32,0.36 \
      --query-instruction $'Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery: ' \
      > qwen-$set-$seed.json
    pnpm docs:eval --json --questions tools/docs/eval/$set.yaml --random 150 --random-seed $seed \
      --min-similarity none --no-query-instruction > none-$set-$seed.json
  done
done
```

Without `--json`, the command prints the same metrics as tables.

## Conclusions

1. **The Qwen3 instruction is the main gain.**

   | Without a floor    | No instruction | Qwen3 instruction |
   | ------------------ | -------------- | ----------------- |
   | Tuning Recall@10   | 0.753          | 0.925             |
   | Tuning MRR         | 0.590          | 0.707             |
   | Held-out Recall@10 | 0.675          | 0.800             |
   | Held-out MRR       | 0.440          | 0.634             |

2. **Floor 0.36 keeps correct questions and typos.**
   - It removes about 88% of the generated random results: about 12% of random strings still get
     vector-only results.
   - It removes the real no-answer false positives of the tuning set. One of the five held-out
     negative questions still gets a vector-only result.
   - The cost is partial words: 2 of 10 (tuning) and 2 of 8 (held-out) lose every expected
     document.
3. **Floor 0.32 is the cautious alternative.** It loses at most one partial word, but about 27% of
   random strings keep vector-only results.
4. **Earlier runs agree.** An earlier calibration on the same sets used a generator that lost its
   low bits, with seeds 156 and 2026. It found the same answerable numbers. Its random false
   positives at 0.36 were 19 of 168 and 15 of 150. The new seeds stay within one or two strings of
   those results, so 0.36 stands for local `qwen3-embedding:0.6b`.
5. **Caveats:**
   - The instruction and the floor were tuned on the tuning set, so its numbers are optimistic.
   - The held-out set is small (8 partial words).
   - A floor is not a reliable answerability signal, so #156 is not fully solved. The follow-ups
     are in
     [search-quality](../../../../docs/ideas/semantic-docs/search-quality.md#no-answer-detection).
