# #201 → #205 → #214: measured retrieval cost

Measured on 2026-11-23 using the five questions in #207, lexical top 10. See the
[generated comparison](2026-11-23-lexical.generated.md),
[machine-readable evidence](2026-11-23-lexical.generated.json) and
[methodology/reproduction commands](../README.md). This is a five-question diagnostic,
not a representative estimate of all agent documentation usage.

## Results

Reading the CLI's `read all:` references costs 242,726 estimated tokens at #201,
133,319 at #205 and 130,516 at #214. With the additional complete contract owners
needed for the Task question, the latter costs are **138,835** and **135,552**.
Compared with #201, that is **42.8%** and **44.2%** less reading for this fixed set.
UTF-8 bytes with those owner reads are 1,154,557 → 669,826 → 655,607.
These numbers exclude search output (separately measured in JSON).

The 44.2% describes this specific **read every TOP-10 result, then complete missing
contract owners** scenario. Agent instructions instead ask the reader to select applicable
documents. This benchmark does not estimate average agent token usage or model that selection
policy. As a separate content-only cross-check, summing the complete authoritative owner
contents recorded in JSON gives 60,529 → 33,489 tokens (#201 → #214, 44.7% less).
That excludes CLI delimiters and all non-owner reads; it is not another measured CLI workflow.

The search implementation trees are identical across the three snapshots. Mode,
limit and absence of embeddings are controlled; document bodies, metadata and corpus
composition differ. This measures the combined refactor effect, not an isolated effect
of document length, section selection or metadata changes.

Strict top-1 authoritative-owner accuracy improves **2/5 → 3/5 → 3/5**:

| Question           | #201 first result                       | #205 / #214 first result    | Interpretation                                                                |
| ------------------ | --------------------------------------- | --------------------------- | ----------------------------------------------------------------------------- |
| Interrupted Create | UI documents/archetypes                 | Interrupted Create recovery | Improved: direct operator procedure wins.                                     |
| Close variants     | Specification operations HTTP reference | Same                        | Useful API entry, but full lifecycle owners are still needed.                 |
| Task completion    | Workflow kernel                         | Task resources              | Correct contract owner; additional gates/attempt owners must be read.         |
| Queue recovery     | Specification documents                 | Document write/commit queue | Correct owner before and after, more focused after the split.                 |
| Session boundaries | Session commands                        | Same                        | Relevant adjacent architecture, but persistence/lifecycle owner is not first. |

The deliberately strict metric does not call the Close API or Session command entry
irrelevant. `unexpectedDocuments` counts documents outside the fixture's complete
owner set, so it is a cost/discovery signal, not a human relevance judgment.

## Regression and contract review

**Task exit-gate rules become a retrieval dependency.** The initial top-10 reads cover
25/25 evidence checks at #201 but only 24/25 after #205 and #214. The missing check is
the authoritative exit-gate evaluation inside the lock and its
`WORKFLOW_GATE_UNSATISFIED` refusal. Those facts moved into
`architecture.workflow.workflow-definitions-and-gates`, absent from these top 10.
The bounded additional owner reads recover **25/25** checks in both candidates.
The workflow navigation/related links provide a route to those owners, but blindly
executing `read all:` is insufficient. Keep full-owner reads for contract changes.

**Session reading has no savings.** With this query, #205 grows from 19,932 to 20,617
tokens; #214 remains slightly above baseline at 20,077. The Session persistence file
remains a complete architecture read. Aggregate gains must not hide this regression.

Excerpts and complete source owners were inspected for the checklist: Create retains
explicit stopped-worker/Git assertions, pinned payloads and refusal on mismatched
effects; Close distinguishes archive-only, exclusive/shared and all-occupant branch
operations and refuses checkout removal under unsettled Turns; Task finish retains
attempt/input/gate requirements and does not mistake preparation status or Specification
completion for Task completion; the queue retains durable journals, dead-executor proof,
trailer **and content** evidence, uncertainty and startup replay; Sessions retain independent
identity, fenced singleton ownership, unknown blocking dispatch, cancellation without
invented settlement and archive/delete refusals. No missing contract fact was found
within these 25 bounded checks after complete owner reads. This does not certify every
invariant, code parity, or every other document in the #206 audit.

No hybrid savings or relevance-floor conclusions are claimed. The three clean
historical snapshots have no compatible fixed embedding indexes; constructing and
calibrating those is a separate model-dependent experiment. #156 already has its own
calibration report under `tools/docs/eval/reports/`.
